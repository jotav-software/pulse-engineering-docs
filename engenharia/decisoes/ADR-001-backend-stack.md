# ADR-001: Backend Architecture & Technology Stack

## Status
Accepted

## Context
The Pulse! platform needs a robust, scalable, and maintainable backend to manage events, ticket sales, facial check-ins, and financial analytics. It must support high-concurrency event drops and ensure zero-fraud ticket validation.

## Decision
We will implement a **Clean Architecture** backend using **Bun.js** and **ElysiaJS**.

### Core Technologies:
- **Runtime**: Bun.js (Ultra-fast, native TS support).
- **Framework**: ElysiaJS (High-performance, type-safe, optimized for Bun).
- **DB (Persistence)**: MySQL (Standard RDS, high reliability, familiar to the team).
- **ORM**: **Prisma** (repositórios em `infrastructure/database/repositories`; ver `prisma/schema.prisma`).
- **Auth**: Better-Auth (Database-backed sessions, similar to Whoollie Food).
- **Documentation**: Swagger (Auto-generated by Elysia).
- **Testing**: Bun Test (Native runner for unit and E2E).

### API namespaces
- **Client (B2C)**: canônico em `/api/client/v1`; espelho legado na raiz para não quebrar mobile em produção.
- **Producer**: `/api/producer/v1`.
- **Auth (Better-Auth)**: `/api/auth/*`.

Composição registrada em `src/presentation/routes/clientApplicationApi.ts` e `src/index.ts`.

### Layered Architecture (Clean):
1. **Domain**: Entities and business invariant rules (No external dependencies).
2. **Application**: Use Cases (Orchestrates domain logic).
3. **Infrastructure**: Database repositories, Mailers, Auth implementation details.
4. **Presentation**: Controllers, Middlewares, API Routes.

## Consequences
- **Positive**: Strict separation of concerns (SOLID), easy to test business logic independently, ultra-low latency API.
- **Negative**: Higher boilerplate compared to simple CRUD frameworks, requires careful dependency injection management.
